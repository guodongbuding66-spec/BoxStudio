# BoxStudio V0.26 Development & Test Report

## Scope

V0.26 focuses on precision editing rather than expanding the box-standard catalog. It adds persistent user guides, deterministic text-baseline and rotation assist, numeric Bezier clip-node controls, and a native cubic PDF clip proof path that emits actual PDF cubic path operators.

V0.26 keeps the V0.24 recoverable batch pipeline and the V0.25 LUT8/LUT16 DeviceLink conversion path. It does **not** claim a general ICC CMM, mAB/mBA support, certified PDF/X, or native cubic clipping in the main production serializer.

## 1. Persistent User Guides

Added `src/smartGuidesV26.js` and `src/v26GuideOverlay.js`.

Project state now has:

```text
userGuides[]
```

Each guide stores:

```text
id
axis = x | y
value (mm)
label
locked
```

Capabilities:

- create vertical or horizontal guide by exact mm value;
- edit guide position numerically;
- remove guide;
- render persistent cyan guide lines on the Design canvas;
- drag unlocked guide lines directly on the Design canvas;
- snap the selected Cross-panel artwork to a nearby user guide using left/center/right or top/middle/bottom selection anchors.

User guides are UI/project editing data. They are not emitted as production artwork.

## 2. Text Baseline Assist

`smartGuidesV26.js` derives deterministic baseline candidates from existing Text / Notice objects using their Panel origin, local Y position, font size, and line spacing convention already used by the PDF text path.

V0.26 can snap a selected Cross-panel artwork object's top/middle/bottom anchor to a nearby text baseline.

The canvas can optionally render the derived baselines as faint violet guides.

This is a layout-assist model; it does not claim full font-metric baseline extraction from arbitrary TTF glyph data.

## 3. Rotation Assist

V0.26 adds deterministic angle assist with candidates from:

- configured angle grid;
- rotation of other Cross-panel objects;
- 90° / 180° / 270° axes relative to other Cross-panel object rotations.

When a grid angle and another object's rotation are equally close, the object-to-object rotation match takes precedence.

The V0.26 workspace currently exposes this as an explicit snap action. V0.25's live drag-time object alignment and equal-spacing guides remain active.

## 4. Numeric Bezier Clip Inspector

Added `src/clipPathV26.js`.

For the selected Bezier clip node, the V0.26 workspace exposes exact normalized values for:

```text
Anchor X / Y
Incoming Handle X / Y
Outgoing Handle X / Y
Smooth / Corner state
Outgoing Segment Type = Line | Curve
```

A Line segment zeroes the outgoing handle of the current node and incoming handle of the next node.

When changing a straight segment to Curve, BoxStudio creates a deterministic 1/3-chord cubic control pair if no controls are already present.

The existing direct-selection canvas workflow from V0.25 remains available for anchor dragging, handle dragging, node insertion and node deletion.

## 5. Native Cubic PDF Clip Proof

Added `src/nativeCubicPdfV26.js`.

For Cross-panel objects that use Bezier clip nodes, the proof serializer emits the clip path using native PDF path operators:

```text
m   move-to
l   line-to
c   cubic Bezier
h   close path
W n apply clip
```

The proof keeps:

- native axial / radial shading;
- multi-stop gradient functions;
- varying gradient-stop alpha soft masks;
- Panel / primitive polygon clips;
- native Bezier Cross-panel object clip;
- DeviceRGB or current verified DeviceLink DeviceCMYK appearance.

Output file from the workspace:

```text
*-v26-cubic-clip-proof.pdf
```

### Important boundary

The main V0.26 production PDF still reuses the V0.25/V0.24 integrated production serializer, where Bezier object clips are deterministically flattened before production clipping.

Therefore V0.26 proves native cubic PDF clipping behavior, but does **not** claim that the main approved-production PDF has switched to native cubic clips yet.

## 6. V0.26 Production Wrapper

Added `src/productionPdfV26.js`.

The production wrapper retains:

- V0.24 approval and DeviceLink binding rules;
- V0.23 native gradient / soft-mask production output;
- V0.25 LUT8 + LUT16 DeviceLink conversion;
- V0.25 Bezier clip production flattening.

Diagnostic serializer identity:

```text
v0.26-native-production
```

The wrapper also reports native cubic proof diagnostics separately so the UI does not confuse proof capability with the production clipping path.

## 7. V0.26 Workspace

Added:

- `src/v26Ui.js`
- `src/v26Ui.css`
- `src/v26GuideOverlay.js`

The workspace provides:

- numeric Bezier anchor / handle controls;
- Line / Curve outgoing segment control;
- persistent user-guide create/edit/remove controls;
- draggable persistent guides on the Design canvas;
- text baseline visibility and snap action;
- rotation assist snap action;
- configurable user-guide / baseline / rotation tolerances;
- native cubic clip proof PDF export;
- V0.26 production PDF export;
- approved V0.26 production export through the existing approval gate;
- LUT8/LUT16 DeviceLink loading and numerical RGB→CMYK test.

V0.25 workspace is hidden while V0.26 is active. V0.24 batch controls remain available because they are still the current recoverable Worker Batch implementation.

CI continues running Syntax + Smoke + every regression suite from V0.10 through V0.26.

## Known Boundaries / Next Work

- browser interaction E2E is still not executed in CI;
- main production PDF still uses flattened Bezier object clips;
- native cubic clipping currently has a dedicated proof serializer only;
- text-baseline assist uses BoxStudio's deterministic layout convention rather than complete font-metric analysis;
- persistent guides are project-local, not collaborative server objects;
- rotation/baseline/user-guide assist are explicit snap actions in V0.26 rather than fully merged into every drag gesture;
- ICC mAB/mBA and general source-profile + destination-profile CMM linking remain future work;
- PDF/X remains Candidate rather than third-party certified;
- no server-side immutable audit, cryptographic approval signature, SSO, or hosted backend is included;
- physical board thickness, bend radius and verified print-stretch compensation remain future work.

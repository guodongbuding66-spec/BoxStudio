# BoxStudio V0.15 Development & Test Report

## Scope

V0.15 focuses on three production gaps left explicit in V0.14:

1. safe SVG shipping-mark / logo import with a production-PDF path;
2. module Web Worker batch PDF generation while retaining IndexedDB artifact recovery;
3. conservative remote project conflict analysis and merge resolution.

This release does **not** claim full Illustrator-compatible SVG rendering, a hosted backend, authenticated multi-user identity, or complete 3D production-artwork texture fidelity.

## 1. Safe SVG Mark / Logo Import

### Added

- `src/svgMark.js`
- SVG Mark / Logo UI inside `src/v15Ui.js`

Supported vector primitives:

- `path`
- `line`
- `rect`
- `circle`
- `ellipse`
- `polygon`
- `polyline`

Supported path commands include M/L/H/V/C/Q/A/Z. Cubic, quadratic and arc geometry is flattened to vector segments for the current production path.

### Safety boundary

The importer rejects embedded/external-capable content including:

- `script`
- `foreignObject`
- `iframe`
- `object`
- `embed`
- `image`
- `use`
- external/data/javascript href references

V0.15 stores imported symbols as `svg-symbol` mark elements. Before PDF generation, each symbol is materialized into BoxStudio line elements using `materializeSvgMarksForProduction()`.

### Production output boundary

The current SVG-mark production implementation is an **outline-safe subset**. It preserves vector geometry as black line work. It does not yet reproduce arbitrary SVG fills, gradients, clip paths, masks, blend modes, CSS inheritance, raster images, or Illustrator-specific appearance semantics.

The V0.15 workspace therefore adds dedicated Draft / Approved PDF buttons that materialize SVG symbols before calling the existing production PDF engine. The older V0.14 Approved PDF button is hidden by the V0.15 layer to avoid silently omitting `svg-symbol` elements.

## 2. Web Worker Batch PDF

### Added

- `src/batchWorkerCore.js`
- `src/batchPdf.worker.js`
- V0.15 Worker Batch UI

Each row can now be processed by a module Web Worker. The worker:

1. applies the selected Master Template;
2. maps the Excel / CSV row into variables;
3. runs Preflight;
4. materializes SVG marks;
5. builds the production PDF;
6. transfers the resulting ArrayBuffer back to the main thread.

The main thread remains responsible for:

- queue state;
- Pause / Resume / Cancel safe boundaries;
- IndexedDB artifact persistence;
- recovered ZIP assembly;
- UI progress.

### Worker eligibility boundary

The worker path intentionally blocks output modes that depend on session-local binary registries not transferred to the worker:

- user TTF outline mode;
- PDF/X candidate mode that may depend on session-local ICC data.

Those outputs remain on the normal production path rather than silently generating a different file.

## 3. Remote Conflict Resolver

### Added

- `src/projectMerge.js`
- V0.15 Remote Conflict Resolver UI

The resolver compares project domains including structure, variables, marks, Profiles, Master Templates, export options, production jobs and batch state.

When a saved Remote Base exists, the three-way analysis distinguishes:

- unchanged;
- local-only change;
- remote-only change;
- both sides changed to the same value;
- conflict.

Non-conflicting domains are auto-mergeable. Conflicting domains require an explicit **Keep Local** or **Use Remote** choice.

When no Remote Base is available, differing domains are treated as conflicts rather than assuming ancestry and silently overwriting data.

`Push Merged Revision` uses the remote envelope as the parent revision and sends the existing REST adapter `If-Match` expected revision.

### Boundary

This is project-domain conflict resolution, not a CRDT/OT collaborative editor. Arrays such as `elements`, `masterTemplates`, `productionJobs`, and `batch` are treated as atomic merge domains rather than per-item collaborative operations.

## 4. Storage Migration

Browser editor state key:

```text
boxstudio-mvp-v15
```

V0.14 and earlier keys remain migration sources.

Remote merge bases are stored separately using:

```text
boxstudio-remote-base-v1:<projectId>
```

IndexedDB artifact storage remains:

```text
boxstudio-artifacts-v1
```

## 5. Automated Regression Coverage

New `tests/v15.mjs` covers:

- SVG path / rect / circle parsing;
- Bezier flattening;
- blocked script / image content;
- `svg-symbol` creation;
- rotation/scaling materialization to production line elements;
- SVG materialization removal before PDF generation;
- worker eligibility allow/deny;
- actual worker-core PDF bytes with `%PDF-` header;
- three-way local-only / remote-only auto merge;
- explicit conflict resolution;
- conservative first comparison without a base.

## Known Boundaries / Next Work

Still not completed in V0.15:

- hosted BoxStudio backend / authenticated users / SSO;
- server-side immutable audit signatures;
- cloud resumable object storage;
- full SVG fills / gradients / masks / clipping / CSS fidelity;
- per-object collaborative merge inside arrays;
- complete 3D production artwork mapping, especially polygon panels and offline renderer;
- worker transfer of user TTF and ICC binary registries;
- factory compensation profiles without verified production data.

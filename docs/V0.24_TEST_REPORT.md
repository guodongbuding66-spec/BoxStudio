# BoxStudio V0.24 Development & Test Report

## Scope

V0.24 moves the V0.23 integrated native-production PDF path into the recoverable Web Worker batch pipeline and into the approved-production export gate. It also makes ICC DeviceLink use reproducible at project and batch level by binding output to a deterministic DeviceLink content identity.

V0.24 does not claim certified PDF/X, cryptographic approval signatures, a hosted authentication system, or a general ICC CMM.

## 1. V0.23 Native Production PDF in Batch Worker

The legacy worker path remains available for older V0.15–V0.23 regression behavior. V0.24 introduces an explicit native batch pipeline that generates each row through the integrated V0.23 production PDF serializer plus V0.24 output binding rules.

V0.24 batch artifacts report:

- serializer identity;
- output color space;
- DeviceLink content fingerprint when used;
- ordinary row fingerprint;
- byte length and file name.

The cached artifact store now preserves those metadata fields without changing the IndexedDB schema version.

## 2. DeviceLink Binary Transfer to Worker

Added `src/workerAssetsV24.js`.

The worker startup payload can now carry three binary asset classes:

- user TTF;
- CMYK OutputIntent ICC;
- RGB→CMYK DeviceLink ICC.

The DeviceLink is parsed again inside the worker. Worker eligibility blocks a V0.24 job when the project declares a DeviceLink fingerprint but the worker has no matching DeviceLink binary.

## 3. Deterministic Batch Run Context

Added `src/batchRunV24.js`.

When a V0.24 batch begins, BoxStudio captures a frozen base production state. Subsequent edits to the live project do not alter the remaining rows in that run.

The queue context stores:

- serializer ID `v0.24-native-production`;
- creation time;
- row count;
- deterministic row-table fingerprint;
- selected batch master ID;
- declared DeviceLink reference;
- frozen base production state.

The row table itself is not duplicated into the queue. Instead, BoxStudio verifies the row-table fingerprint before and during execution. If rows change, the run is blocked and must be restarted rather than silently mixing configurations.

## 4. Project-bound DeviceLink Identity

`src/iccDeviceLinkV23.js` now exposes a deterministic 64-bit FNV-1a content fingerprint and a copy of the loaded source bytes for worker transfer.

The project can persist a lightweight `exportOptions.deviceLinkRef` containing:

- name;
- byte size;
- content fingerprint;
- RGB→CMYK declaration;
- LUT tag type;
- CLUT grid size.

The ICC binary itself remains session memory only.

Added `src/productionPdfV24.js`.

Rules:

- no declared DeviceLink → output stays on the RGB native-appearance path even if an unrelated DeviceLink is loaded in memory;
- declared DeviceLink + no loaded binary → production export is blocked;
- declared DeviceLink + different fingerprint → production export is blocked;
- declared DeviceLink + exact fingerprint match → V0.23 native appearance conversion may use that DeviceLink.

The content fingerprint is a deterministic change-detection identity, not a security signature.

## 5. Approved-production Output Gate

Added `src/productionOutputV24.js`.

Approved production export now requires all of the following:

1. selected production job is approved;
2. current structure/artwork/export settings match the approved production fingerprint;
3. preflight remains acceptable under the existing approval model;
4. current role may perform `export-approved`;
5. if a DeviceLink is declared, the exact DeviceLink content fingerprint is loaded.

`src/productionJobs.js` now also records successful approved exports as `exported` audit events with file name, format, serializer, actor, role and revision.

This is still a local application audit model, not an immutable or authenticated server audit.

## 6. V0.24 Workspace

Added:

- `src/v24Ui.js`
- `src/v24Ui.css`

The workspace provides:

- V0.24 production PDF export;
- approved V0.24 production PDF export;
- DeviceLink load-and-bind;
- session unload without removing project binding;
- explicit binding removal;
- exact binding/gate status;
- V0.24 native Web Worker batch;
- pause / resume / cancel;
- retry failed or cancelled rows;
- recoverable IndexedDB artifacts;
- recovered ZIP with serializer/color metadata;
- frozen-run compatibility warning when row data changes.

The older V0.16 worker section and older approved-export buttons are hidden while V0.24 is active.

## 7. Storage Migration

Primary browser project state:

```text
boxstudio-mvp-v24
```

`boxstudio-mvp-v23` and earlier supported keys remain migration sources.

Artifact database remains:

```text
IndexedDB: boxstudio-artifacts-v1
```

## 8. Regression Coverage

Added `tests/v24.mjs`.

Coverage includes:

- deterministic DeviceLink identity;
- DeviceLink worker collection / transfer / hydration;
- worker eligibility with exact DeviceLink match;
- frozen batch base-state behavior;
- row-table mutation detection;
- V0.24 worker serializer routing;
- integrated PDF byte generation;
- artifact serializer/color metadata persistence;
- approved output gate with DeviceLink present;
- approved output gate blocking when DeviceLink is missing;
- successful re-binding of the exact DeviceLink;
- approved-export audit event creation;
- direct V0.24 production PDF generation.

Legacy regression compatibility is preserved: V0.19 worker tests continue receiving the V0.19 serializer unless a frozen V0.24 batch state explicitly selects the V0.24 pipeline.

## Known Boundaries / Next Work

- browser interaction E2E is still not executed in CI;
- DeviceLink support remains the verified RGB→CMYK LUT8/mft1 subset;
- the DeviceLink content fingerprint is not cryptographic authentication;
- approved-job audit remains client-side/local;
- full server-side immutable audit, SSO and approval signatures are not implemented;
- V0.24 does not yet add ICC LUT16, mAB/mBA or arbitrary source-profile + destination-profile CMM linking;
- clip path insertion/deletion and Bezier handles remain future work;
- Illustrator-style smart guides can still be expanded beyond equal-gap detection;
- physical board thickness, bend radius and verified print-stretch simulation remain future work.

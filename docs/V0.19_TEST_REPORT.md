# BoxStudio V0.19 Development & Test Report

## Scope

V0.19 moves the V0.18 safe SVG appearance subset from proof-only rendering into an explicit production-export path and adds an explicit cross-panel artwork object that is clipped into intersected carton panels.

The release intentionally does **not** claim full Illustrator Appearance fidelity, native PDF gradient shading, CMYK color conversion of imported SVG fills, certified PDF/X output, or RIP/monitor soft-proof equivalence.

## 1. Production Appearance Materialization

Added `src/productionAppearance.js`.

Supported production materialization:

- explicit solid SVG fills → vector polygons;
- linear gradients → deterministic vector triangle tessellation;
- radial gradients → deterministic vector triangle tessellation;
- basic geometric clipPath → clipped vector polygons;
- basic binary geometric mask → clipped vector polygons;
- opacity / fill-opacity → preblended against white for the current vector-only serializer;
- imported SVG outline geometry remains vector linework.

Gradient percentages are resolved against the painted primitive bounds. A regression test verifies that a 0%→100% gradient produces multiple distinct output colors instead of collapsing to one color.

### Production appearance boundaries

- gradients are approximated by flat-color vector triangles rather than native SVG/PDF gradient shading in the PDF serializer;
- opacity is currently preblended against white instead of emitted as PDF transparency groups;
- CSS cascade, patterns, filters, blend modes and raster image fidelity are not implemented;
- complex curved filled paths outside the V0.18 safe subset remain outline-only;
- imported RGB appearance colors are not converted through the loaded CMYK ICC profile in V0.19.

## 2. Appearance-aware Production SVG / PDF

Added `src/exportV19.js`.

The new production path keeps the existing structure output and mark output while adding V0.19 appearance polygons:

- CUT / CREASE / PERF / GLUE;
- spot-name metadata / separation handling from the existing print profile path;
- text / technical outline / user-TTF outline modes;
- Barcode + QR;
- shipping symbols;
- imported SVG outlines;
- supported SVG fills / gradient approximations;
- cross-panel clipped fragments.

New browser export controls:

- `Export V0.19 Production PDF`
- `Export V0.19 Production SVG`

The SVG path injects the V0.19 appearance layer before dieline geometry when the current 2D editor SVG is available.

The PDF path writes supported appearance polygons as vector fill paths. The current fill color operators are DeviceRGB; V0.19 does not claim ICC-based conversion of those imported SVG colors.

## 3. Cross-panel Artwork Object

Added `src/crossPanelArtwork.js`.

A panel-local imported SVG mark can be promoted to a document-global `cross-panel-artwork` object.

At production materialization time BoxStudio:

1. resolves the artwork in document coordinates;
2. materializes supported SVG fills and outline vectors;
3. intersects them with each carton panel;
4. clips polygon artwork into panel fragments;
5. clips outline segments at panel boundaries;
6. converts the fragments back to panel-local coordinates for export.

The V0.19 workspace exposes X / Y / W / H controls for the first cross-panel object and reports touched panels plus fill/outline fragment counts.

This is explicit cross-panel artwork. It is different from the V0.18 fold-bleed diagnostic, which only reports one-sided/two-sided artwork near folds.

### Cross-panel boundaries

- clipping is vector geometric clipping, not RIP trapping;
- panel polygons are triangulated for polygon clipping;
- there is no automatic semantic image reflow, warp, board stretch or fold-radius compensation;
- one cross-panel object can span multiple panels, but collaborative per-object ordering is still future work.

## 4. Batch Worker Integration

`src/batchWorkerCore.js` now routes generated PDFs through `buildProductionPdfV19()`.

The existing batch flow remains:

`Master Template → row variables → Preflight → Worker PDF → IndexedDB artifact → ZIP/recovery`

V0.19 batch PDFs therefore use the same appearance-aware serializer as the explicit V0.19 PDF export.

Worker TTF / ICC transfer rules from V0.16 remain in force.

## 5. Workspace

Added:

- `src/v19Ui.js`
- `src/v19Ui.css`

The V0.18 folded proof remains visible. V0.19 adds a separate production-materialization workspace below it instead of replacing the proof view.

The workspace shows:

- imported SVG appearance count;
- gradient source count;
- production polygon count;
- cross-panel artwork count;
- appearance warning count;
- production SVG/PDF export controls;
- cross-panel promotion and document-global bounds;
- per-object panel/fragment diagnostics.

## 6. Storage Migration

Primary browser state key:

```text
boxstudio-mvp-v19
```

V0.18 and all earlier supported keys remain migration sources.

No IndexedDB artifact schema change is introduced in V0.19.

## 7. Automated Regression Coverage

Added `tests/v19.mjs` covering:

- gradient appearance → multiple vector production polygons;
- percentage gradient coordinate regression;
- multiple output colors from a 0%→100% gradient;
- cross-panel placement across adjacent generated panels;
- fill fragment clipping into multiple panels;
- outline line clipping into multiple panels;
- cross-panel diagnostics;
- removal of raw `svg-symbol` / `cross-panel-artwork` objects after production materialization;
- V0.19 PDF header / producer path;
- RGB vector fill operators in the generated PDF;
- batch worker use of the V0.19 serializer.

GitHub Actions runs syntax checks, smoke tests, and every regression suite from V0.10 through V0.19.

The V0.19 CI run with the new regression completed successfully.

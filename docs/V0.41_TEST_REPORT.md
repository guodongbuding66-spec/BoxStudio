# BoxStudio V0.41 Test Report

## Scope

V0.41 verifies the new template-generator/reference interaction layer without weakening the existing production regression gates.

## Real browser acceptance path

Headless Chrome performs the following user-visible workflow:

1. start in the free professional editor shell;
2. verify `freeAccess=true` and `approvalRequired=false`;
3. open Template Center;
4. search `0427`;
5. select FEFCO 0427;
6. continue after the real page reload;
7. verify the selected template persisted;
8. choose Outer/External dimensions;
9. set L/W/H to `320 × 210 × 80 mm`;
10. choose Corrugated Kraft;
11. Apply & Generate;
12. continue after the second real reload;
13. verify size mode, dimensions and material persisted;
14. enter Design mode;
15. select Multi Face scope;
16. set Fold to 55%;
17. verify Fold persistence;
18. open the existing V0.35 2D↔3D Review.

Final successful signal from V0.41 workflow run #6:

```text
PASS template=fefco-0427 mode=external material=corrugated-kraft fold=55
```

## Failures found during development

### Attempt 1 — iframe + virtual time

Result: no PASS/FAIL signal.

The initial driver embedded the real application in an iframe and combined iframe navigation with `--virtual-time-budget`. The browser completed resource loading but the test driver did not reliably continue across the iframe lifecycle.

No product assertion had failed.

### Attempt 2 — iframe without virtual time

Result: no PASS/FAIL signal.

Removing virtual time did not solve the core iframe lifecycle problem.

### Attempt 3 — document replacement check

A real race was identified in the test driver: after template selection the old iframe document still exposed `BoxStudioV41` and `.workspace`, so the driver could incorrectly treat the old document as the newly reloaded app.

The driver was changed to require a different `contentDocument` object before continuing. The approach remained too fragile for a multi-reload acceptance test.

### Final fix — same-page staged reload state machine

The browser harness was changed to use the application directly in the test page instead of an iframe.

Progress is persisted in `sessionStorage`:

```text
stage 0 → select template → real reload
stage 1 → configure generator → real reload
stage 2 → verify state → Design Scope → Fold → 2D↔3D Review → PASS
```

`--virtual-time-budget=60000` is used only to ensure async ES-module initialization and the staged reload flow have enough browser time to complete.

This produced the first complete real-browser PASS.

## Defects found during development

### 1. Live solver executed before V0.38 persistence

Initial V0.45 attempts listened to the bubbling `change` event and re-solved too early. V0.38 had not yet finished its own `commit -> persist -> render` lifecycle, so V0.45 sometimes solved the previous CAD document and the new edit then overwrote it.

Final repair:

- use the V0.38 post-render DOM mutation as the reliable lifecycle boundary;
- read the latest persisted `dielineV38` document;
- diagnose whether continuity is actually broken;
- solve only when required;
- use an application guard so the V0.45 reopen/rerender path cannot create an observer loop.

### 2. R5 -> R6 originally changed only Arc metadata

The first radius-edit implementation set `rx=ry=6` on an existing R5 Fillet but left the R5 tangent points unchanged. That does not represent the same sharp corner with a true R6 Fillet and was rejected.

Final repair:

- store original sharp-corner provenance when the feature is created;
- restore the original node and source CUT edges;
- recompute the R6 setback from the source angle;
- move both tangent points;
- regenerate the native Arc;
- fail closed if later independent topology edits make lossless restoration unsafe.

The upgraded Node and Chrome tests explicitly require the R6 reflow behavior.

## Fail-closed cases

V0.45 intentionally rejects or blocks unsafe cases including:

- zero-length curve direction;
- Fillet/Chamfer on a node that is not degree 2;
- Fillet/Chamfer when either source edge is not a straight CUT;
- invalid near-0-degree / near-180-degree corner angle;
- requested setback longer than an incident edge;
- generic circular Arc radius below half the chord;
- missing corner-feature provenance;
- corner tangent node with additional edited topology;
- source corner edge edited such that lossless restore is no longer safe;
- stored G1/C1/G2 topology no longer consisting of two Cubics;
- Fillet Arc radius drifting away from its feature parameter.

## External acceptance not claimed

The automated suite proves BoxStudio's own geometry model, browser interaction, native vector serializers and regression compatibility. It does not prove acceptance by external CAD/CAM/RIP/die-cutting equipment.

External production-tool validation remains a separate acceptance layer.

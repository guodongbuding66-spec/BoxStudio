# BoxStudio V0.25 Development & Test Report

## Scope

V0.25 focuses on two production-facing areas: direct-selection quality for Cross-panel clip paths and higher-precision ICC DeviceLink conversion. The release adds Bezier clip nodes with insertion/deletion and editable tangent handles, object-to-object Smart Guides, resize size-match hints, and verified ICC LUT16 (`mft2`) support in addition to the existing LUT8 (`mft1`) path.

V0.25 continues to use the V0.24 approved-production gate and deterministic batch infrastructure. It does **not** claim a general ICC CMM, mAB/mBA support, certified PDF/X, or browser interaction E2E coverage.

## 1. Bezier Cross-panel Clip Paths

Added `src/clipPathV25.js`.

A Cross-panel clip can now use a node model:

```text
crossClip.type = bezier-polygon
node.p   = normalized anchor
node.in  = incoming handle offset
node.out = outgoing handle offset
node.smooth = mirrored-tangent mode
```

Implemented operations:

- convert a legacy polygon clip to Bezier nodes;
- create a new inset Bezier clip;
- drag anchors in document space;
- drag incoming/outgoing tangent handles;
- mirrored smooth-handle editing;
- break tangent symmetry for a gesture;
- insert a node on a segment;
- remove a node while preserving the minimum 3-node polygon rule;
- reset a node to a corner;
- create a smooth-handle preset;
- flatten cubic segments into a deterministic production polygon.

### Curve-preserving insertion

Node insertion uses De Casteljau subdivision. For an existing cubic segment, inserting at `t` updates the adjacent handles and creates the new node so the original cubic curve is preserved mathematically rather than approximated by simply dropping an anchor on the line.

## 2. Production Materialization of Bezier Clips

`src/crossPanelArtwork.js` now accepts both:

- legacy `crossClip.points`; and
- V0.25 `crossClip.nodes`.

Bezier paths are flattened to a normalized polygon before the existing object clip → Panel clip → production fragment pipeline.

Therefore the V0.25 clip participates in:

```text
2D Cross-panel Artwork
→ object clip
→ Panel intersection
→ production fill/outline fragments
→ native production PDF
→ Panel Artwork Atlas / Folded proof consumers
```

The flattened clip is still polygonal at production-materialization time. BoxStudio does not claim native PDF cubic clipping in V0.25.

## 3. Direct Selection Overlay

Added `src/v25CanvasOverlay.js` and replaced the loaded V0.23 overlay in `index.html`.

For a selected Cross-panel artwork object:

- cyan anchors represent clip nodes;
- orange handles represent active cubic tangents;
- orange diamonds represent segment insertion points;
- click/drag anchor → move node;
- click diamond → insert a node;
- Alt+click anchor → delete a node;
- drag tangent handle → edit curve;
- Alt while dragging a tangent → break mirrored symmetry for the current gesture.

The selected clip-node index is stored in `crossPanelEdit.clipNodeIndex`.

## 4. Illustrator-style Object Smart Guides

Added `src/smartGuidesV25.js`.

V0.25 adds object-to-object snapping between Cross-panel artwork objects for:

### Translation

- left ↔ left/center/right;
- center ↔ left/center/right;
- right ↔ left/center/right;
- top ↔ top/middle/bottom;
- middle ↔ top/middle/bottom;
- bottom ↔ top/middle/bottom.

The nearest candidate within tolerance wins independently for X and Y.

### Resize

The single-object resize path can identify nearby matching widths and heights. With aspect lock enabled, the nearest width or height target drives proportional size matching.

### Guide colors in V0.25 overlay

- magenta: object alignment / size match;
- orange: equal-gap spacing;
- green: existing Panel/Grid snapping.

Holding Alt bypasses smart snapping for the active gesture.

New state defaults:

```text
objectGuides = true
objectGuideToleranceMm = 3
smartSpacing = true
spacingToleranceMm = 3
clipNodeIndex = 0
```

## 5. ICC LUT16 DeviceLink Support

`src/iccDeviceLinkV23.js` has been extended while preserving its public API and deterministic content fingerprint.

Supported verified DeviceLink types are now:

```text
A2B0 LUT8  / mft1 / 8-bit
A2B0 LUT16 / mft2 / 16-bit
```

Both remain restricted to:

```text
Profile class: link
Input color space: RGB
Output color space: CMYK
Channels: 3 → 4
```

### LUT16 parser

The V0.25 LUT16 path validates and reads:

- 3 input / 4 output channels;
- CLUT grid points;
- 3×3 s15Fixed16 matrix;
- input-table entry count;
- output-table entry count;
- 16-bit input tables;
- 16-bit 3D CLUT;
- 16-bit output tables.

Values are normalized to 0..1 and processed through the same deterministic transform stages:

1. input tables;
2. matrix;
3. trilinear CLUT interpolation;
4. output tables.

`getDeviceLinkInfo()` and project binding references now also expose precision and table-entry counts.

### Explicit boundary

V0.25 still does **not** implement:

- LUT16 with non-RGB→CMYK channel layouts;
- mAB/mBA multi-process elements;
- arbitrary source RGB profile + destination printer profile linking;
- rendering-intent selection through a general CMM;
- black-point compensation;
- proof-device simulation.

## 6. V0.25 Production Wrapper

Added `src/productionPdfV25.js`.

The V0.25 production route reuses the validated V0.24 approval/DeviceLink binding layer and integrated native PDF serializer while adding the V0.25 shared clip and ICC capabilities.

Diagnostic serializer identity:

```text
v0.25-native-production
```

Single-project export file:

```text
boxstudio-v0.25-production-native.pdf
```

Successful approved V0.25 exports are recorded through the existing production-job `exported` audit event.

## Known Boundaries / Next Work

- browser interaction E2E is still not executed in CI;
- Bezier clips are flattened for production clipping rather than emitted as native cubic PDF clipping paths;
- mAB/mBA and general ICC CMM linking remain future work;
- Smart Guides do not yet include text baselines, arbitrary rotation-axis snapping, or persistent user guides;
- no server-side immutable approval audit or cryptographic approval signature exists;
- PDF/X remains Candidate rather than third-party certified output;
- physical board thickness, bend radius and verified print-stretch simulation remain future work.

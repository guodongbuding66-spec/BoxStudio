## 3. Production PDF verification

Generated `test-production-v07-spot.pdf` from the default RSC demo project with spot dielines / overprint enabled.

Verified that the PDF bytes contain:

- `%PDF-1.6`
- `/Separation /CutContour`
- `/Separation /Crease`
- `/OP true`
- `/OPM 1`

The file was reopened with PyMuPDF and rendered through the PDF verification renderer successfully. The generated test page is 1 page and measures about 3816.0 × 959.5 mm, matching the current default large RSC demo geometry.

This verifies that the file is structurally readable and the spot/overprint resources are present. It does **not** imply PDF/X compliance; V0.7 has no OutputIntent ICC or complete PDF/X metadata.

## 4. PDF / AI import verification

`assets/sample-dieline.pdf` is generated from BoxStudio's own production output and then parsed by `src/pdfAiImport.js`.

The parser recovered:

- CUT paths
- CREASE paths
- GLUE paths
- panel candidates
- `CutContour / Crease / Perforation / Glue` Separation names

The same PDF-compatible content saved with `.ai` is accepted as `AI / PDF-compatible`.

A deflate-compressed PDF content stream was also tested separately against the FlateDecode path.

## 5. TrueType exact outline verification

The parser was tested with a system-installed TrueType font **only inside the test environment**. No font file is bundled or distributed with BoxStudio.

Verified:

- `cmap` lookup
- glyph metrics
- simple glyph outlines
- text outline generation
- quadratic path output
- PDF path conversion
- no PDF text operator (`BT`) in exact-outline mode

V0.7 intentionally rejects CFF/CFF2 OTF fonts.

## 6. Known test boundary

A fully automated real-browser E2E pass is not claimed for V0.7. Core modules, import/export files, and production serialization are tested independently. Browser-side file upload and interactive drag workflows should still be run manually in Chrome/Edge before production deployment.

## Real browser acceptance

`tests/v38-browser-e2e.js` is run in real Headless Chrome and validates an end-to-end CAD interaction instead of only importing modules.

The gate performs:

1. open Dieline CAD;
2. persist `dielineV38` into project storage;
3. select a real SVG edge;
4. convert the edge from CUT to CREASE;
5. convert the selected edge to Cubic Bézier;
6. insert a node on the cubic;
7. persist exact X numeric edit;
8. drag the inserted node on the SVG canvas and verify the saved mm coordinate;
9. select a split cubic edge;
10. drag C1 control handle and verify the saved Bézier control point;
11. run Preflight;
12. generate DXF and verify CREASE layer;
13. generate SVG and verify Crease spot metadata;
14. generate Dieline PDF in the browser.

## Failures caught during development

### Browser E2E driver: SVG `.click()`

Initial browser run failed because an SVG path did not expose HTMLElement-style `.click()` in the runner. The test driver was repaired to send a real MouseEvent; production assertions were not weakened.

### Browser Dieline PDF: Node-only `Buffer`

A later browser run progressed through real CAD editing and Preflight, then failed at PDF generation:

```text
ReferenceError: Buffer is not defined
```

The domain suite had passed because it executes under Node. The product code was fixed by replacing `Buffer.byteLength` with UTF-8 byte length calculated using `TextEncoder`, making the same PDF builder usable in browser and Node.

## Explicit non-claims

A green V0.38 software gate does **not** certify:

- AutoCAD / ArtiosCAD / Esko round-trip;
- third-party PDF preflight/RIP behavior;
- arbitrary polygon/Bezier bleed offset correctness;
- real press / die cutter / crease compensation;
- factory sample folding;
- arbitrary edited panel topology automatically repositioning all artwork in the legacy full Production PDF pipeline.

Those remain explicit engineering or EXT acceptance items.

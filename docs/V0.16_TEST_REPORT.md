# BoxStudio V0.16 Development & Test Report

## Scope

V0.16 focuses on three production-oriented extensions on top of V0.15:

1. transfer of uploaded TTF and ICC binaries into the module PDF Worker;
2. object/field-level three-way project merge for high-conflict project domains;
3. a unified Panel Artwork Texture Atlas used as the data/rendering basis for future 3D material mapping.

This release does **not** claim hosted multi-user backend, immutable server audit, full CRDT collaboration, full Illustrator SVG appearance fidelity, or print-RIP-certified 3D soft proofing.

## 1. Worker Binary Asset Transfer

### Added

- `src/workerAssets.js`
- source-byte retention in `src/fontRegistry.js`
- source-byte access in `src/iccRegistry.js`
- session asset initialization in `src/batchPdf.worker.js`
- updated eligibility logic in `src/batchWorkerCore.js`
- V0.16 Worker Batch UI in `src/v16Ui.js`

### Behavior

The PDF Worker can now receive the currently loaded user TTF and ICC binary data once when the Worker starts.

After initialization, each batch row reuses the same in-worker registries rather than retransferring binary files for every PDF.

Worker eligibility now behaves as follows:

- technical/vector text without user TTF: allowed;
- TTF outline mode: allowed only when a user TTF binary is available for transfer;
- PDF/X candidate mode: allowed only when an ICC binary is available for transfer;
- missing required binary asset: blocked explicitly rather than silently degrading output.

The main thread still owns queue metadata, Pause / Resume / Cancel, IndexedDB persistence and recovered ZIP creation.

## 2. Object-Level Three-Way Merge

### Added

- `src/projectMergeV2.js`
- V0.16 Granular Remote Merge UI

Granular domains:

- `elements` by object `id`, then by field;
- `masterTemplates` by `id`, then by field;
- `productionJobs` by `id`, then by field;
- custom Customer / Packaging Rule / Mark Template / Mark Asset maps by key, then by field.

Other project domains continue to use conservative atomic three-way comparison.

### Examples

If Local changes `elements[sku].x` while Remote changes `elements[sku].y`, V0.16 can auto-merge both edits.

If Local and Remote both change `elements[sku].x` differently from the same base, the resolver creates an explicit field conflict:

```text
elements[sku].x
```

and requires `Keep Local` or `Use Remote`.

Presence/deletion conflicts are also surfaced explicitly.

This is still not a CRDT/OT collaborative editor. Ordering conflicts and arbitrary unkeyed arrays remain conservative.

## 3. Panel Artwork Texture Atlas

### Added

- `src/panelArtwork.js`
- V0.16 Panel Artwork Texture Atlas UI

The texture plan normalizes supported artwork into panel-local rendering commands for:

- text / conditional package notice;
- shipping icons;
- lines and shapes;
- Barcode + QR;
- imported `svg-symbol` vector marks.

The atlas exposes:

- panel count;
- artwork element count;
- render command count;
- artwork commands outside panel bounds;
- browser Canvas preview for each panel.

This provides a shared artwork representation suitable for later Three.js material textures and UV mapping.

### Boundary

V0.16 does not yet claim that the existing folded 3D renderer uses this atlas for final production soft proofing. In particular, polygon-panel UVs, seam continuity, color-management and print distortion simulation are still future work.

## Known Boundaries / Next Work

Still not completed in V0.16:

- hosted BoxStudio backend / authenticated users / SSO;
- server-side immutable audit signatures;
- cloud resumable object storage;
- true per-object collaborative ordering / CRDT semantics;
- complete SVG fill / gradient / clipping / CSS fidelity;
- direct use of the Panel Artwork Atlas as the folded 3D material source;
- polygon-panel UV mapping and seam continuity;
- color-managed 3D soft proofing;
- factory compensation profiles without verified production data.

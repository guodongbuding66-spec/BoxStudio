# V0.37 Implementation Invariants

- PostgreSQL is the authority for sessions, project heads, revisions, workflows, audit events, idempotency records and production archives.
- `artwork_revisions.snapshot` and `snapshot_hash` are immutable after insert. PostgreSQL rejects UPDATE/DELETE independently of application code.
- `production_archives` are immutable after insert and bind to exactly one approved project revision.
- Revision creation locks the project row before validating `expectedRevision`; concurrent writers cannot both advance the same head.
- Audit append takes a dedicated transaction advisory lock before choosing the next sequence and previous hash.
- Idempotency is scoped to `(actor, operation, key)` and binds the key to a canonical request hash.
- The same key + same request replays the stored response; same key + different request fails closed.
- Bearer tokens are never stored in plaintext; PostgreSQL stores only SHA-256 token hashes.
- V0.36 in-memory service remains available as a regression/reference implementation, while `npm start:api` moves to V0.37 durable runtime.

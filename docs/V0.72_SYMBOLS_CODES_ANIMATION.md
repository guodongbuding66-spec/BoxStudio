# V0.72 箱面标识、编码生成器与动画

本轮继续核对 Pacdora 指定 150010 页面和 Packform 实际编辑器。Packform 的文字、面板图文、折叠、场景和项目流程可观察；Pacdora 指定模型仍停留在“构建模型”，因此不把未加载出的操作记为实测。完整能力边界延续 [V0.71 对照矩阵](V0.71_REFERENCE_FEATURE_MATRIX.md)，本轮增加以下交付。

| 功能 | 本轮实现 |
|---|---|
| 箱面标识库 | 17 款原创矢量图形；独立唛头的“标识”页签提供搜索与缩略图，纸盒组件库也可插入 |
| 堆码参数 | 含底箱的层数 1–99、最大高度 0.1–20 m、上部重量 1–9999 kg；图形中的数值可编辑 |
| 温度范围 | 最低/最高温度 −99 至 99 °C；拒绝颠倒或相同上下限 |
| 其余标识 | 向上、小心轻放、怕雨、禁止堆码、禁止手钩、禁止夹持、夹持/吊起位置、重心、怕晒、禁止翻滚、禁止手推车、回收 |
| 直接生成编码 | Code 128/39/93、EAN-13/8、UPC-A、ITF-14、GS1-128、QR、Data Matrix、PDF417、Aztec 共 12 种 |
| 内容、变量和错误反馈 | 输入即预览；可绑定 `{{sku}}` 等变量；商品码可自动补校验位，非法编码或过密尺寸阻止插入/下载 |
| 插入后的编辑 | 独立编码是可编辑对象，支持修改内容、物理宽高、比例缩放、撤销、图层与 JSON 备份 |
| 原有运输组合 | 原条码＋QR仍是一个不可拆分对象，保持250×80 mm或200×64 mm整体规格 |
| 独立码下载 | 矢量 SVG 按毫米尺寸输出，PNG 声明正确的300 DPI元数据；插入唛头后参与原尺寸生产PDF |
| 实际动画文件 | 纸盒“导出 → 3D 场景与导出 → 动画导出”；展开组装或360°旋转，6/10秒，1280×960 WebM |
| 录制交互 | 进度提示、录制中防止参数变更、取消及关闭清理；不下载取消后的残缺文件 |

标识的预览、PDF与纸盒3D贴图共享相同路径，数字使用矢量路径。图形表达常见储运要求，不声称经过ISO认证。GS1输入应使用自己的已分配标识，生成器不分配商品编号。新增编码器使用固定版本 `@bwip-js/generic@4.11.4`，构建时复制到站内并保留许可证，运行时不上传编码内容。

新编码会检查白底静区、与其他可见对象的重叠、方向及模块密度：线性码至少0.254 mm，二维模块至少0.4 mm。上述门槛是本产品的数字稿策略，实际纸张、印刷和扫描设备仍需按使用场景验证。中文QR按UTF-8保存；条形码的字符范围由对应编码标准决定。

视频采用浏览器原生Canvas/MediaRecorder，以实际折叠网格逐帧绘制；目标采样12fps，实际帧数受设备性能影响。支持WebM录制的Chrome/Edge/Firefox可用；没有原生编码器时禁用并提示。透明场景视频使用白底，PNG仍支持透明背景。当前没有MP4/GIF或摄影级PBR导出。

## 验证入口

- `tests/v72.mjs`：162项符号路径、参数边界、编辑/备份、编码、静区、生产门控和动画状态检查。
- `tests/v72-external-decode.py`：将13份最终生产PDF以300DPI栅格化，再用独立ZXing读取12种编码和中文QR，与输入比较。
- `tests/v72-browser-e2e.js`：完整生产入口，1280px桌面和390px手机上的标识搜索、层数修改/错误、12种编码预览、内容编辑/撤销、真实PNG/PDF/JSON/WebM下载、取消、模式切换及布局。
- `tests/v72-chrome-runner.mjs`：Chrome实际写到磁盘的文件逐一与生成字节的SHA-256比较。
- `tests/v72-native-files.py`：对原生下载的PDF和PNG独立扫码，检查PNG物理DPI，再使用ffprobe/ffmpeg解码视频首段/中段/末段，拒绝空视频或静态帧。

GitHub CI运行这些检查后才合并发布。尚未完整交付的参考能力包括大型盒型/素材库、完整字体排版、摄影级灯光、云端团队同步及AI设计；不能以本轮新增功能代替这些差距。

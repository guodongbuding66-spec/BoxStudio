# BoxStudio V0.8 Test Report

## 1. Static syntax validation

Executed against every application module and the smoke test entry:

```bash
for f in src/*.js tests/smoke.mjs; do node --check "$f"; done
```

Result: all checked JavaScript files exited with code 0.

## 2. Automated smoke test

Command:

```bash
node tests/smoke.mjs
```

Actual terminal result:

```text
BoxStudio V0.8 smoke tests passed
```

V0.8 keeps the V0.7 geometry/import/barcode/QR/fold/topology coverage and adds automated checks for:

- custom CUT / CREASE Separation names
- ICC header parsing and `acsp` validation path
- CMYK ICC detection
- PDF/X-4 Candidate gate
- `/OutputIntents`
- `/DestOutputProfile`
- `/GTS_PDFXVersion (PDF/X-4)`
- XMP `pdfxid:GTS_PDFXVersion`
- removal of Base14 Helvetica resources in Candidate mode

The automated ICC used by the unit path is a synthetic header-only CMYK fixture created in memory. It validates BoxStudio's serializer and gate logic; it is **not** a production color profile and is never shipped to users.

## 3. PDF/X boundary

V0.8 intentionally labels this path **PDF/X-4 Candidate**, not certified PDF/X-4.

The application now writes the major structures required for the intended production route when the gate passes, but this test suite does not replace Acrobat Preflight, callas pdfToolbox, an RIP, or a printing plant's own acceptance checks.

A real production run must use a legitimate CMYK ICC profile supplied by the user or printer.

## 4. Binary-safe PDF assembly

The PDF builder was changed from a pure UTF-8 string concatenator to a byte-chunk assembler. XRef offsets are computed from real byte lengths, allowing arbitrary ICC bytes to be embedded without corrupting object offsets.

Normal Production PDF remains available when PDF/X Candidate is off.

## 5. Browser packaging check

The project remains a static browser application with relative module paths. It can be served using:

```bash
python -m http.server 8080
```

Interactive file pickers (TTF / ICC / imported dielines) still require a manual browser pass before production deployment.

## 6. Real CMYK ICC integration verification

A local Ghostscript CMYK ICC profile was loaded **only for test execution** and was not copied into the project. BoxStudio generated `test-production-v08-pdfx-candidate.pdf`.

`pdfinfo` reopened the file and reported:

```text
PDF version: 1.6
PDF subtype: PDF/X-4
Metadata Stream: yes
Encrypted: no
```

Ghostscript also parsed the generated PDF successfully with `-sDEVICE=nullpage` and exit code `0`.

This verifies that the byte offsets, ICC stream, OutputIntent and metadata are structurally readable by two independent PDF consumers. It still does not substitute for a full production preflight profile.

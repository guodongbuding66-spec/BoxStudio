## Failure discovered and fixed during development

### 1. Unrelated 0427 production-gate coupling

Initial V0.44 final-PDF test reused the edited FEFCO 0427 document directly. V0.39 correctly blocked that fixture with existing template-specific review conditions including `PANEL_REMAP_REQUIRED` and `CUT_INTERSECTION`.

This did not indicate a V0.44 split or serializer error. The test was corrected to keep:

- 0427 for real native curve editing and topology reconstruction;
- a production-safe baseline document with an actual V0.44 split Cubic for final Production PDF serializer acceptance.

The final-PDF assertion remains strict: native split Cubics must still appear as PDF cubic operators.

### 2. Selection restoration after CAD reopen

The first real Chrome run showed the split operation itself succeeded: the new node and child Cubics were present in the DOM, but the new node was not selected. The original V0.44 reopen helper restored selection through nested `requestAnimationFrame` calls, which was not deterministic under headless Chrome virtual-time execution.

The product was fixed rather than relaxing the test:

- CAD reopen remains synchronous;
- selection is restored synchronously immediately after V0.38 render/bind;
- a microtask retry is used only as fallback.

### 3. Legacy node controls

The V0.38 `Add Node on Edge` path historically refused native Arc splitting. V0.44 now routes the existing button through `splitEdgeV44()` and routes reversible split-node deletion through exact `mergeSplitNodeV44()`.

The real Chrome test explicitly exercises this legacy UI path.

# BoxStudio V0.14 Development & Test Report

## Scope

V0.14 focuses on production continuity and persistence. It does **not** claim to provide a hosted backend or identity provider. The browser app now has explicit adapters and storage layers that can be connected to a compatible service later.

## 1. Recoverable Batch Artifacts

### Added

- `src/artifactStore.js`
- `src/persistentBatch.js`
- V0.14 persistent queue UI

Generated PDF bytes can now be stored in browser IndexedDB by queue ID + row index.

A page refresh no longer means all completed batch PDFs have to disappear. On resume, BoxStudio reconciles queue metadata with persisted artifacts:

- completed + artifact present → stays completed
- completed + artifact missing → returns to pending
- pending/failed state + artifact present → recovered as completed

The recovered ZIP is built from the files that actually exist in IndexedDB and includes `boxstudio-artifacts.json` as a manifest.

### Boundary

IndexedDB is browser-local storage. It is not cloud persistence and can still be cleared by browser/site-data controls.

## 2. Production Role Model

### Added roles

- Viewer
- Operator
- Approver
- Admin

### Permission model

Operator:

- create production snapshot
- submit
- revise
- export an already approved revision

Approver:

- approve
- reject
- export an already approved revision

Admin:

- all production actions, including delete

Viewer:

- read-only production role

Permissions are enforced in `src/productionJobs.js`, not only by disabled buttons in the UI.

### Boundary

This is a local authorization model. It is **not authentication**. There is currently no login server, SSO, signed identity, or tamper-resistant audit service.

## 3. Project Persistence Layer

### Added

`src/projectStore.js`

The project persistence model now has a portable envelope with:

- schema name/version
- project ID
- revision
- parent revision
- created/updated metadata
- updatedBy
- project state snapshot

### Local project library

Browser localStorage can hold multiple project envelopes instead of only one current editor state.

Supported operations:

- list
- save
- revise
- load
- delete
- JSON import/export

### REST adapter contract

A generic REST adapter is included for future cloud/project-server work.

Expected endpoints:

```text
GET    /projects
GET    /projects/:id
PUT    /projects/:id
DELETE /projects/:id
```

`PUT` and `DELETE` can send `If-Match` using the expected project revision.

The BoxStudio repository currently does **not** include a production server implementation for this contract.

V0.13 and earlier keys remain migration sources.

New project-level fields include:

- `projectId`

- `remoteProjectEndpoint`
- `lastRemoteSyncAt`
- `productionRole`

## 5. UI Changes

V0.14 adds a new **Persistent Production** section containing:

- Persistent Batch Artifacts
- Production Roles & Approval
- Project Persistence

The older V0.12 batch queue block and V0.13 production block are hidden by the V0.14 layer to avoid duplicate controls. Their underlying modules remain for migration/regression compatibility.

## Known Boundaries / Next Work

Still not completed in V0.14:

- hosted BoxStudio backend
- authenticated users / SSO
- server-side audit immutability
- resumable cloud object storage
- arbitrary SVG mark-symbol production export
- full 3D panel texture rendering of every production vector element
- Web Worker PDF generation
- conflict-resolution UI for simultaneous remote edits

These remain explicit future work rather than being represented as finished features.

# V0.81 完整项目包

纸盒与独立唛头的“项目”窗口新增“完整项目包 · ZIP”。项目 JSON 仍保留，换设备继续编辑时推荐项目包。

## 实际包含的内容

- 当前设计 JSON：结构、自定义刀版、嵌入图片、变量、字体引用、混合文字样式、局部工艺与材质参数。
- 纸盒场景：可独立摆放的包装与道具、位置 / 旋转 / 大小、显隐状态，以及引用的外部模型。重复引用同一模型仅存一份；隐藏模型也会打包。
- 独立唛头：正唛和侧唛两张画板及当前编辑面，独立于纸盒工作区。
- 项目中印刷验证记录所引用的照片与检测仪报告原文件，保留文件名、MIME 类型、修改日期及原始字节。记录中的“未评级”不会被转换成软件生成的 ISO 等级。
- manifest.json：项目类型、版本、附件清单、长度、SHA-256。

ZIP 为标准未压缩格式，整体上限 128 MB；JSON 50 MB；单模型 30 MB，单照片 / 报告 20 MB。模型已在原导入时转成自包含的规范 GLB，恢复时不重复换算单位或重置原点。

## 打开流程与故障处理

选择项目包 → 检查 ZIP 目录、CRC、项目与附件 SHA-256 → 展示可审阅的文件清单 → 点击打开 → 验证实际 GLB 网格 → 恢复原文件 → 最后提交设计。纸盒包打开纸盒工作区；唛头包打开独立唛头工作区，不替换纸盒设计。

缺失、损坏、重复、额外的文件、路径穿越、未支持的压缩方式或未来版本均会阻止打开。原浏览器缺少模型 / 校验附件时，导出会明确报错，避免静默遗漏。存储写入失败不会替换当前文档或破坏纸盒撤销历史。内容寻址的附件写入可安全重试；失败导入中已写入但未引用的附件可能暂留浏览器，现阶段没有自动回收功能。

## 验证

- `npm run test:v81`：两类项目、两面唛头、去重、元数据、SHA / CRC、截断、缺失 / 重复 / 额外附件、非法路径、清单版本、字段和深度限制。
- `node tests/v81-browser.mjs <Chrome>`：原生 ZIP 下载与上传、两个隔离浏览器的实际迁移、恢复后的 3D 渲染、完整场景 GLB 的 Khronos 验证、390 / 768 / 1440 px 弹窗边界、独立正侧唛与混合文字、缺失附件处理、存储配额失败恢复。
- 原有 V0.80 实体纸板、折叠与扫描流程继续回归。

## 明确边界

项目包不是离线安装包。内置字体与素材由网站提供，临时加载的自有 TTF / ICC 需在新设备重新加载。全量项目库、收藏、其他项目及本地预设列表不包含在单个项目包内；当前项目已应用的自定义材质参数会保留。未接入云端同步、多人协作、商业站素材库镜像或硬件印刷评级。V0.80 说明中“JSON 不含模型 / 证据”的限制仍适用于 JSON，V0.81 的 ZIP 项目包补齐了这个迁移断点。

## V0.81.1 业务字段兼容

普通变量和 CSV / Excel 行中的 `type: "model"` 不再被当成模型附件；只有携带模型资源记录的对象会进入附件清单。真实场景里缺少模型资源的记录仍会拒绝打开。单元测试及两个浏览器的完整迁移流程覆盖纸盒变量、批量数据和独立唛头变量的保留。

# BoxStudio V0.23 Development & Test Report

## Scope

V0.23 closes the largest production-output gap left by V0.22: native PDF gradient shading and varying-opacity soft masks are now integrated into a complete BoxStudio production-PDF serializer instead of existing only in a separate appearance-proof PDF. The release also adds a verifiable ICC RGB→CMYK conversion subset, graphical clip-point editing, and live equal-spacing guides for Cross-panel artwork.

V0.23 still does **not** claim certified PDF/X output, arbitrary ICC source/output profile chaining, arbitrary SVG filter/luminance-mask fidelity, RIP trapping, calibrated monitor soft proofing, or physical board deformation simulation.

## 1. Integrated Production PDF V0.23

Added `src/productionPdfV23.js`.

The V0.23 PDF route combines in one document:

- CUT / CREASE / PERF / GLUE dielines;
- configured spot-color separation names;
- dieline overprint resources;
- normal text and notice variables;
- technical-vector or user-TTF outline text modes;
- barcode + QR groups;
- shipping icons;
- shape / line marks;
- Panel-local imported SVG outline segments;
- Cross-panel imported SVG outline fragments;
- native PDF axial shading (`/ShadingType 2`);
- native PDF radial shading (`/ShadingType 3`);
- multi-stop stitching functions;
- uniform alpha through `ExtGState`;
- varying gradient-stop opacity through PDF luminosity soft masks;
- editable Cross-panel clip geometry;
- object z-order traversal;
- existing PDF/X-4 Candidate OutputIntent / XMP / TrimBox / BleedBox route.

Native imported appearance is no longer forced through the V0.19 triangle-tessellation route for the V0.23 PDF export. The V0.19 PDF remains available as a compatibility fallback.

Export file:

```text
boxstudio-v0.23-production-native.pdf
```

### PDF/X boundary

The existing mode remains explicitly named **PDF/X-4 Candidate**. Candidate mode still requires a loaded CMYK OutputIntent and outlined text, but BoxStudio does not claim Acrobat, callas, RIP, or other third-party certification.

## 2. Verified ICC RGB→CMYK DeviceLink Subset

Added `src/iccDeviceLinkV23.js`.

V0.23 does not pretend that a normal CMYK OutputIntent performs artwork conversion. Instead, the first actual conversion path accepts only an explicit ICC DeviceLink profile that passes all of these checks:

- ICC signature `acsp`;
- profile class `link`;
- input color space `RGB`;
- output color space `CMYK`;
- `A2B0` tag exists;
- `A2B0` type is LUT8 / `mft1`;
- LUT has exactly 3 input channels and 4 output channels;
- CLUT and input/output tables are within file bounds.

The implemented transform applies:

1. input tables;
2. the LUT8 3×3 matrix;
3. trilinear interpolation through the 3D CLUT;
4. output tables.

When such a verified DeviceLink is loaded, native imported SVG solid/gradient RGB colors are converted to 4-channel values and the V0.23 native shading path uses `/DeviceCMYK`.

When no verified DeviceLink is loaded, imported native appearance remains `/DeviceRGB`. A normal printer/output ICC continues to serve as OutputIntent only.

Current limitation: this release supports the verified RGB→CMYK LUT8 (`mft1`) DeviceLink subset only. LUT16, mAB/mBA, source-profile + destination-profile linking, rendering-intent pipelines, black-point compensation, and arbitrary ICC CMM behavior are not claimed.

## 3. Graphical Clip-point Editing

Added `src/clipEditorV23.js` and replaced the loaded V0.22 overlay with `src/v23CanvasOverlay.js`.

For a selected Cross-panel object with an editable clip polygon:

- every normalized clip point is shown as a cyan canvas handle;
- handles are draggable directly in document space;
- document coordinates are inverse-rotated back into object coordinates;
- coordinates are normalized to 0..1 and persisted in `crossClip.points`;
- rotated objects retain stable clip-point editing;
- clip geometry continues to feed production materialization, native SVG export, V0.23 PDF clipping, and folded 3D panel fragments.

The V0.23 workspace can create a full rectangular clip or 10% inset clip before graphical editing.

## 4. Live Smart Spacing Guides

Added `src/smartSpacingV23.js`.

During Cross-panel drag operations, V0.23 evaluates neighboring stationary Cross-panel objects. When the moving selection is within the configured tolerance of equal gaps, it snaps to:

- equal left/right horizontal spacing; or
- equal top/bottom vertical spacing.

The Design canvas shows orange equal-spacing guide labels with the resolved mm gap.

Settings added to `crossPanelEdit`:

```text
smartSpacing = true
spacingToleranceMm = 3
```

Holding Alt continues to bypass snapping for the current drag.

## Known Boundaries / Next Work

- PDF/X remains Candidate, not certified output;
- ICC conversion currently supports only verified RGB→CMYK LUT8 (`mft1`) DeviceLink profiles;
- ordinary source RGB profiles + printer CMYK profiles are not automatically linked by an ICC CMM;
- arbitrary SVG luminance masks, filters, patterns and blend modes are not fully implemented;
- smart spacing currently detects equal opposing gaps, not every Illustrator-style guide relation;
- clip points are draggable, but path-segment insertion/deletion and Bezier clip handles remain future work;
- Batch Worker still uses the existing production serializer path and has not yet been switched to V0.23 native production PDF;
- browser interaction E2E was not run in this release; automated coverage is module/regression based;
- hosted backend, Auth/SSO, immutable server-side audit, cloud object storage, board thickness/bend radius, and verified print-stretch simulation remain future work.

# BoxStudio V0.10 Test Report

## Scope

V0.10 introduces the first reusable packaging-rules and master-template layer on top of the existing V0.8 editor/export engine, plus an in-browser profile/master-template manager.

### Added modules

- `src/rules.js` — declarative packaging rule profiles.
- `src/customerProfiles.js` — customer defaults, locked variables, preferred mark template and packaging-rule binding.
- `src/markTemplates.js` — reusable shipping-mark layouts and the 250×80 / 200×64 barcode+QR presets.
- `src/masterTemplates.js` — create, validate, serialize, parse and apply master-template snapshots while optionally preserving live SKU/order variables.
- `src/profileUi.js` + `src/profileUi.css` — UI for customer profile, packaging rule, mark template and saved master-template management.
- `src/lockedVariablesUi.js` — enforces customer-profile variable locks in the editor UI.
- `tests/v10.mjs` — focused V0.10 regression coverage.

## Default production profile

The default state now uses:

- Customer profile: `us-export-master`
- Packaging rule profile: `us-side-seal`
- Mark template: `us-side-seal-master`
- Locked defaults: origin country, destination country, dimension unit and weight unit

The browser storage key was migrated to `boxstudio-mvp-v10`, with V0.9/V0.8 and earlier keys retained as migration sources.

## Rule coverage

The US side-seal rule profile checks:

- SKU, N.W., G.W., CRN, Contract No., origin and destination are present.
- Package index is within package count.
- Multi-package jobs contain a package notice.
- CRN is bound in at least two mark locations.
- Barcode + QR group exists.
- Barcode + QR group keeps the 3.125:1 production ratio.
- Standard 250×80 mm and compact 200×64 mm presets are recognized.
- Aspect-ratio lock is required.

These rule checks are included in `runPreflight()` together with customer-profile and mark-template validation.

## Profile / Master Template UI

The top bar now exposes a **Profiles** manager that can:

- Apply a customer profile.
- Switch Packaging Rule Profile.
- Apply a reusable mark template.
- Save the current project as a Master Template snapshot.
- Apply a saved Master Template while preserving live SKU/order data.
- Export Master Templates as JSON.
- Import Master Templates from JSON.
- Delete saved Master Templates.

Variables listed in the active customer profile's `lockedVariables` are rendered read-only in the editor and receive a `LOCKED` badge.

## Automated tests

GitHub Actions runs:

1. `node --check` on every `src/*.js` and `tests/*.mjs` file.
2. The original `tests/smoke.mjs` regression suite.
3. `tests/v10.mjs` covering rules, customer profiles, mark templates, master-template serialization/application and preflight integration.

The V0.10 test suite verifies, among other cases:

- Default US side-seal state has no packaging-rule errors.
- Missing CRN is rejected.
- Package 4/3 is rejected.
- Two CRN bindings are detected.
- US customer defaults and locks validate.
- Compact mark template produces a 200×64 mm locked group.
- Master templates preserve live SKU values when applied with `preserveVariables: true`.
- Preflight exposes Packaging Rule Profile, Customer Profile and Mark Template checks.

The latest CI run after loading the variable-lock UI completed successfully: syntax checks, the legacy smoke suite and the V0.10 profile/master-template suite all passed.

## Repository cleanup

The obsolete V0.9 payload-staging workflow and `.sync` payload fragments were removed. The repository now uses the normal `main` source tree and the single CI workflow.

## Known limitations

- Master Templates are still browser-local project data; there is no account/database synchronization yet.
- Packaging rules currently include `generic` and `us-side-seal`; more customer/factory rule profiles still need to be added from verified specifications.
- Master-template rename/duplicate/version-history controls are not implemented yet.
- Factory-specific crease compensation, die-board allowances and device-specific tolerances still require verified production data and are not invented by BoxStudio.

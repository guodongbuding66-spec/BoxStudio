# BoxStudio V0.20 Development & Test Report

## Scope

V0.20 focuses on three production-workflow gaps left by V0.19: native SVG gradient preservation, direct cross-panel editing in the main 2D canvas, and cross-panel artwork participation in the folded 3D artwork atlas. It also adds an explicit object z-order model.

V0.20 intentionally does **not** claim native PDF gradient shading, ICC device-link RGB→CMYK conversion, full SVG/CSS appearance fidelity, calibrated soft proofing, or physical board deformation simulation.

## 1. Native SVG Gradient Production Path

Added `src/nativeSvgV20.js`.

The V0.20 SVG export path keeps supported imported SVG appearance as native SVG definitions rather than flattening every gradient into V0.19 triangle tessellation.

Supported in the native SVG layer:

- `linearGradient`;
- `radialGradient`;
- native gradient stops and stop opacity;
- supported solid fills;
- supported basic `clipPath`;
- supported binary geometric mask;
- panel clipping;
- cross-panel clipping;
- object rotation and non-uniform scale;
- z-order traversal through the V0.20 object-order model.

For cross-panel artwork, the same document-global gradient is clipped by a union of carton panel shapes. This keeps one native gradient coordinate system across panel boundaries instead of regenerating an unrelated gradient per panel.

### SVG boundary

The native path still follows the safe SVG subset established in V0.18. It does not add CSS selector cascade, filters, patterns, raster images, blend modes, complex luminance masks, or unsupported curved filled paths.

## 2. Cross-panel Artwork → Panel Artwork Atlas → Folded 3D

`src/panelArtwork.js` now materializes `cross-panel-artwork` fragments while building each panel plan.

Cross-panel output can now enter the same folded proof chain as panel-local artwork:

`Cross-panel object → panel clipping → panel-local fragments → Panel Artwork Atlas → folded texture proof`

New atlas diagnostics include `crossPanelFragments`.

The panel texture renderer now also accepts the resulting `production-polygon` commands, so clipped fill fragments can appear in folded textures instead of being limited to the V0.19 export serializer.

This is still a geometry/placement proof; it is not RIP trapping or print-stretch simulation.

## 3. Direct Cross-panel Editing in the Main 2D Canvas

Added `src/v20CanvasOverlay.js`.

When the Design SVG is present, each `cross-panel-artwork` object receives a document-global overlay with:

- imported SVG outline preview;
- cross-panel bounds;
- selected-state highlight;
- direct drag move;
- lower-right resize handle;
- aspect-ratio lock support;
- selected-object persistence.

The overlay writes the updated object bounds back to the V0.20 browser project state.

## 4. Object Z-order

Added `src/objectOrder.js`.

Supported operations:

- normalize z-order;
- send to back;
- move backward;
- move forward;
- bring to front;
- stable ordered traversal for objects without an explicit z-index.

Cross-panel materialization preserves the source object's z-index, and `panelArtwork.js` sorts generated panel commands by object order.

This establishes deterministic stacking for the current local editor. It is not yet a collaborative ordering CRDT.

## 5. V0.20 Workspace

Added:

- `src/v20Ui.js`
- `src/v20Ui.css`

The workspace exposes:

- V0.20 Native Gradient SVG export;
- V0.19 PDF tessellation fallback export;
- native gradient / primitive counts;
- cross-panel object and folded-atlas fragment counts;
- selected-object z-order controls;
- explicit production-boundary notices.

V0.19's separate production workspace is hidden when V0.20 is active, while the V0.18 folded proof remains available because it now consumes the cross-panel-enabled atlas automatically.

## 6. PDF and Color-management Boundary

V0.20 does **not** relabel the existing PDF path as native-gradient PDF.

The V0.20 UI explicitly keeps PDF on the tested V0.19 tessellation serializer. Native PDF axial/radial shading is future work.

Likewise, imported RGB appearance colors are not passed through a true ICC device-link or PCS→output conversion engine. Existing ICC OutputIntent/PDF-X Candidate behavior remains separate from actual pixel/vector color conversion.

## 7. Storage Migration

Primary browser state key:

```text
boxstudio-mvp-v20
```

`boxstudio-mvp-v19` and all earlier supported keys remain migration sources.

No IndexedDB artifact schema change is introduced in V0.20.

## 8. Automated Regression Coverage

Added `tests/v20.mjs` covering:

- cross-panel artwork materialization into the Panel Artwork Atlas;
- cross-panel fragment commands in folded panel plans;
- native linear-gradient definitions;
- native cross-panel clipping markup;
- V0.20 native SVG layer injection;
- z-order normalization and send-to-back behavior;
- cross-panel overlay data generation.

CI continues running syntax checks, smoke tests, and every regression suite from V0.10 through V0.20.

## Next Work

- native PDF axial/radial shading objects;
- ICC-based RGB/CMYK conversion using an actual color-management engine;
- alpha transparency groups and luminance-mask fidelity;
- richer cross-panel handles: rotation, multi-select and snapping;
- native cross-panel fill editing directly in the primary 2D renderer rather than an overlay layer;
- per-object clip-path editing;
- board thickness, bend radius and print-stretch simulation;
- hosted backend, authentication/SSO and immutable server-side audit.
